# WSL 수동 설정 가이드

## 설치 전 결정

WSL은 Windows와 Linux 파일·네트워크·자격 증명 경계를 연결할 수 있다. 조직 정책이 WSL 사용을 허용하는지, 필요한 배포판과 버전, Docker 또는 GUI 통합 필요 여부를 확인한다. 민감한 Windows 사용자 프로필이나 프로젝트 밖 경로를 무분별하게 마운트하지 않는다.

## 설치와 초기화

1. 관리자 PowerShell에서 조직이 승인한 Microsoft 문서 절차에 따라 WSL 구성 요소를 설치한다. 재부팅 요구 사항을 따른다.
2. 승인된 Linux 배포판만 설치하고, 첫 실행에서 별도 Linux 사용자와 강력한 비밀번호를 만든다.
3. 배포판 안에서 패키지 인덱스와 보안 업데이트를 적용한다. 패키지는 배포판의 신뢰된 저장소 또는 승인된 내부 미러에서만 설치한다.
4. `wsl --status`와 `wsl -l -v`로 상태와 배포판 버전을 확인한다. 출력에 사용자 경로나 민감 정보가 있다면 공유 전에 삭제한다.

## 파일·권한 운영

- 소스 작업은 가능하면 Linux 홈 디렉터리 또는 조직이 지정한 작업 위치에서 수행한다.
- Windows 드라이브 마운트 아래에서 Linux 권한·대소문자·심볼릭 링크에 의존하는 작업은 사전에 호환성을 확인한다.
- Windows 자격 증명, SSH 키, `.env`, 브라우저 데이터가 자동으로 보이는지 점검하고 필요 이상으로 공유하지 않는다.
- `sudo`는 필요한 명령에만 사용하며, 비밀번호 없는 sudo나 광범위한 권한 변경을 설정하지 않는다.

## 네트워크와 정리

배포판 내부에서 서비스 포트를 열면 Windows 방화벽·네트워크 정책과 함께 검토한다. 외부 바인딩이 필요한 진단은 승인된 테스트망에서만 수행한다. 작업 완료 후 `wsl --shutdown`으로 실행 중인 인스턴스를 종료할 수 있으며, 배포판 내 캐시·로그 정리는 보존 정책과 프로젝트의 무시 규칙을 따른다. 배포판 등록 해제는 데이터 삭제를 수반하므로 별도 승인과 백업 확인 없이 수행하지 않는다.
