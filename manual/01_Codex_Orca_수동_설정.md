# Codex + Orca 수동 설정 가이드

## 목적과 경계

Codex는 작업 디렉터리의 코드·문서를 보조하는 도구로, Orca는 조직이 승인한 별도 진단 또는 연동 도구로 취급한다. 두 도구를 연결하기 전에 Orca의 서버 주소, 인증 방식, 데이터 처리 범위를 담당자에게 확인한다. 인증을 우회하거나 로컬 설정을 복사해 공유하지 않는다.

## Codex 준비

1. 조직이 승인한 Codex 배포 경로에서 설치하거나 로그인한다.
2. 작업할 저장소를 연 뒤, 프로젝트의 `AGENTS.md`와 보안 정책을 먼저 읽는다.
3. 사용자 범위의 설정 위치와 프로젝트 범위의 설정 위치를 구분한다. 실제 사용자 설정 파일을 저장소로 복사하지 않는다.
4. 필요한 값은 환경 변수로 주입한다. 예: PowerShell 세션에서 `$env:ORCA_ENDPOINT`처럼 일시 설정하고, 값을 터미널 출력이나 문서에 남기지 않는다.
5. `templates/codex.config.toml.template`을 복사해 로컬 전용 설정으로 사용한다. 자리표시자를 실제 값으로 바꾼 복사본은 추적 대상에서 제외한다.

## Orca 연동 전 검토

- 최소 권한 계정 또는 범위가 제한된 토큰을 사용한다.
- 엔드포인트는 HTTPS와 조직이 승인한 호스트만 사용한다.
- 보내는 컨텍스트가 소스 코드, 진단 로그, 개인 정보, 고객 데이터를 포함하는지 확인한다.
- 도구가 명령 실행·파일 쓰기·네트워크 접근을 요청하면 기본값은 거부하고, 필요한 범위만 명시적으로 승인한다.

## MCP 또는 유사 연동 설정

`templates/codex.mcp.toml.template`은 Burp·IDA·JADX·Notion용으로 **비활성화된** 값 없는 예시다. 복사본에서 검증된 연동만 하나씩 활성화하고, 승인된 실행 방법과 인증 수단을 지정한다. 실행 파일 경로는 장비마다 다르므로 템플릿에 절대 경로를 넣지 않는다. Orca의 MCP 사양이 확인되지 않았다면 이 파일에 억지로 추가하지 말고, Orca 공급자 또는 조직의 승인 문서를 따른다.

설정 후 새 세션에서 다음만 검증한다.

1. 연동 항목이 시작되며 인증 값이 화면이나 로그에 출력되지 않는지 확인한다.
2. 읽기 전용 상태 확인 요청을 한 번 실행한다.
3. 의도하지 않은 파일 쓰기나 외부 전송 권한 요청이 없는지 확인한다.
4. 실패 시 토큰을 붙여 넣지 말고, 오류 코드와 민감 정보가 제거된 로그만 검토한다.

## 종료·해제

작업이 끝나면 세션 환경 변수를 닫고, 더 이상 필요 없는 로컬 복사 설정과 캐시를 조직 정책에 따라 제거한다. 토큰 노출이 의심되면 즉시 해당 자격 증명을 폐기·재발급하고 담당자에게 보고한다.
