# Windows Diagnostics Bootstrap — 안전 운영 원칙

이 문서는 Windows 진단 환경을 **수동으로** 준비할 때의 공통 규칙이다. 자동 설치, 계정 정보 수집, 라이선스 우회, 시스템 보안 기능 비활성화는 이 범위에 포함하지 않는다.

## 시작 전 확인

- 회사 또는 개인 장비의 소프트웨어 설치·네트워크 캡처·USB 사용 정책을 확인한다.
- 관리자 권한은 설치 프로그램이 명시적으로 요구할 때만 사용한다. 평소 실행은 표준 사용자 권한을 우선한다.
- 설치 파일은 공급자 공식 사이트 또는 조직이 승인한 배포 위치에서 받고, 게시된 서명·해시를 대조한다.
- 설치 날짜, 버전, 다운로드 출처, 승인 티켓을 별도 기록한다. 비밀 값·라이선스 키·토큰은 기록하지 않는다.
- 진단 대상의 소유자와 캡처·로그 보관 기간을 사전에 합의한다.

## 저장소에 넣지 않을 것

다음은 이 프로젝트와 Git 저장소에 절대 커밋하지 않는다.

- API 키, 액세스 토큰, 쿠키, 세션, SSH 개인 키, VPN 프로필
- 사용자별 설정 파일, `%APPDATA%`/`%LOCALAPPDATA%` 덤프, 브라우저 프로필
- 라이선스 키, 활성화 파일, 상용 도구 설치본, 다운로드 설치 관리자
- 패킷 캡처(`.pcap`, `.pcapng`), 메모리 덤프, 시스템 로그, 고객 데이터
- WSL 디스크(VHDX), 패키지 캐시, 컨테이너 이미지, 진단 산출물

템플릿에는 `${ENVIRONMENT_VARIABLE}`처럼 **값 없는 자리표시자**만 둔다. 실제 값은 조직의 승인된 비밀 관리 수단 또는 사용자 환경 변수에만 보관한다.

## 권장 폴더와 실행 흐름

프로젝트에는 문서·템플릿·재현 가능한 스크립트만 둔다. 설치 파일과 결과물은 프로젝트 밖의 승인된 작업 위치에 보관한다. 수동 설치 후에는 아래 순서로 최소 검증한다.

1. 프로그램의 버전 화면과 디지털 서명을 확인한다.
2. 테스트용 비민감 데이터로 기능을 확인한다.
3. 설정에서 저장 위치와 자동 업데이트 정책을 점검한다.
4. 실제 대상 작업 전, 승인·범위·보존 기간을 다시 확인한다.

문제가 생기면 화면 캡처나 로그를 공유하기 전에 사용자 이름, 호스트 이름, IP, 토큰, 요청 본문 등 민감 정보를 제거한다.
